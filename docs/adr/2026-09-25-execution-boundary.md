# ADR：免安裝中性封裝與原生資料語義

日期：2026-09-25。狀態：依使用者限制形成的設計提案，待實作驗證。

## 背景

部分 API 改寫與執行檔命名曾破壞檔案訪問及工具自啟動；歷史遷移亦受路徑影響。使用者要求統一處理，禁止端點安装驅動／服務，最後澄清限制针对交付程式，使用者資料無名稱限制。

## 決策

1. 主方案採中性免安裝前端、結構介面 adapter、未改內容的原引擎及獨立持久資料。不是完整安全沙箱。
2. 不繼續擴大 Win32 檔案、環境或 DNS hooks。啟動時配置環境，不對 API 回傳結果偽造名稱。
3. 交付命名與執行語義分離。使用者資料保留原結構；不替換 JSON、工具名稱、歷史原文或使用者文件。
4. session 以引擎持久資料為權威，前端索引可重建；升級前備份，實際續接驗證後才切換。
5. 中性前端不直接透傳原 TUI。正式依賴選擇取決於已文件化介面能否覆蓋批准、取消、恢復及擴展能力。
6. 二進位字串、原始簽章、子進程內部環境及必要通知不宣稱已消除名稱；嚴格要求這些亦無原名時重新決策。

## 後果

可保留本機 Windows 工具與資料語義，避免模擬效能及遠端同步成本。代價是需維護小型前端和版本化 adapter，且不能保證限制任意子進程所有主機訪問。公開中性設定與引擎原始環境之間仍有一次有意義的配置转换。

## 替代方案

Sandboxie 因驅動／服務限制排除。遠端隔離和 QEMU TCG 保留在設計取捨中，未獲部署授權且在最新資料豁免下沒有必要。純改名 hooks 與修改原二進位內容不採用。SDK 本身不提供「沒有原引擎內部名稱」的保證。
